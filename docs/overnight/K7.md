# K7: Check-in screen with a countdown ring (overnight run)

Branch `kean/k7-check-in`, cut from `kean/k6-pin-gate` at `7714610`. Built unattended: every question was answered with the recommended option, and each answer is listed under "Decisions taken on Kean's behalf".

## Plan

### Requirements, restated

- K7 (PRD D8, UI-3): the Check-in screen. Full screen, dark and high contrast, large "Are you okay?", a countdown ring driven by `onPhase.stageEndsAt` (epoch ms), the current stage (whisper, loud or PIN gate) shown, and a Cancel button at least 60 pt tall that calls `tapCancel()`. Depends on K3.
- One-handed: Cancel sits in the bottom half of the screen, full width, so a thumb reaches it without moving the grip.
- At the PIN gate the wearer goes to PIN entry. K3's `PhaseNavigator` already does this; the screen must not offer a Cancel that Swift ignores at that stage (`SessionManager.tapCancel` returns early at `pinGate`).
- Accessibility labels for VoiceOver, in a sensible reading order (question, stage, time left, Cancel).
- Component tests with the module mock.
- Done when: usable one-handed in the dark.

### Grounding in the existing code

- `app/src/screens/CheckInScreen.tsx`: K3's skeleton (question, stage hint, seconds as text, a standard Cancel). K7 replaces its body and keeps its `tapCancel` wiring and error display.
- `app/src/session/SessionStateProvider.tsx`: the only subscriber to `onPhase`. The ring needs the stage's full length to know how full to be, and the event only carries the end. The provider is where events arrive, so it records when each phase step was first seen.
- `app/src/session/useNow.ts` and `describe.ts` (`secondsUntil`): the clock hook and the rounding the countdown already uses.
- `app/src/navigation/phaseNavigation.ts`: opens Check-in, moves to PIN entry at the PIN gate, and returns to the session on `monitoring`. Unchanged.
- `app/src/ui/ActionButton.tsx`, `theme.ts`: the shared 60 pt button and night colors. K7 adds a large size and an accessibility hint to the button rather than a second button.
- `app/__tests__/screens/CheckInScreen.test.tsx` and `app/test-utils/renderApp.tsx`: route-tree tests against the native mock; extended here.
- `app.json`: the React Compiler is on, so render stays pure (no `Date.now()` during render).

### Phases

1. Tests first (RED): pure countdown maths (seconds left, ring fraction, lit ticks, clamping, unknown end); the phase-seen timestamp (kept for a repeated event, reset for a new stage); the ring (lit tick count, progressbar role and value); the view (stage per step, Cancel size and hint, Enter PIN in place of Cancel at the PIN gate, error); the screen in the real route tree (ring drains as time passes, Cancel calls `tapCancel`, a failed Cancel shows a message, navigation unchanged).
2. Code (GREEN): `src/checkIn/countdown.ts`, `src/checkIn/stages.ts`, `src/checkIn/CountdownRing.tsx`, `src/checkIn/CheckInView.tsx`, `src/session/phaseState.ts`, `phaseSeenAt` in the provider, the large `ActionButton`, and the screen as a thin container.
3. Verify: jest, tsc, expo lint, swift test, simulator build (no native packages, so no prebuild).
4. Docs, commit and push.

### Risks

- **No native drawing library.** `react-native-svg` is not installed and adding it means a native rebuild for all four phones. Mitigation: the ring is 60 plain `View` ticks rotated around the centre, so no new package and no rebuild.
- **The event has no stage start.** Without it the ring cannot know its full length. Mitigation: the provider stamps the time it first sees each (phase, stage, stageEndsAt); the ring's length is `stageEndsAt - seenAt`. A relaunch mid-stage starts the ring full for the time that is left, which is acceptable. Adding `stageStartedAt` to the contract would touch Justin's `SessionManager` and `Shared/Contracts.swift`, outside Kean's folders.
- **Cancel at the PIN gate does nothing in Swift.** Mitigation: at the PIN gate the button becomes "Enter PIN" and opens PIN entry.
- **Layout can't be measured in Jest.** "Bottom half" and "in the dark" are checked by structure (Cancel is the last element, full width, 120 pt) and by hand on the phone; the test guide covers it.
- **Re-rendering 4 times a second.** The ring ticks every 250 ms for a smooth drain; 60 small views is cheap, and only this screen uses the fast clock.

## Decisions taken on Kean's behalf

1. **Ring from plain Views, not `react-native-svg`.** Adding SVG means a native package and a rebuild on all four phones the night before. 60 ticks look like a ring, drain smoothly through a 10 s demo stage at 4 updates a second, and cost nothing natively.
2. **The ring's length comes from when the app first saw the stage.** `onPhase` only carries `stageEndsAt`. The provider stamps `phaseSeenAt` when a new (phase, stage, stage end) arrives, and the ring is `remaining / (stageEndsAt - phaseSeenAt)`. Events arrive within milliseconds of the stage starting, so this matches the real length. After a relaunch mid-stage the ring starts full for the time that's left; the seconds are always exact. Rejected: hard-coding the PRD's stage windows (they differ in demo mode and would drift from Swift), and a `stageStartedAt` contract field (it would mean editing Justin's `SessionManager` and `Shared/Contracts.swift`).
3. **Enter PIN in place of Cancel at the PIN gate.** `SessionManager.tapCancel` returns early at the PIN gate, so a Cancel there would do nothing. PhaseNavigator moves to PIN entry by itself; the button is the wearer's way through if that ever doesn't happen.
4. **Cancel is 120 pt, full width and the last thing on the screen**, twice the 60 pt minimum, with a 32 pt bold label, so a thumb finds it without looking. It is the app's primary blue (5.4:1 against the background; the white label is 3.5:1, which passes AA for text this large).
5. **Cancel whispers too.** Swift accepts `tapCancel` during the whisper stage, so Cancel is offered there with the hint "Nod if you're okay, or tap Cancel."
6. **A failed Cancel keeps Cancel up** with a message naming the error and saying to nod or tap again, rather than disabling anything. A second `tapCancel` is harmless: Swift ignores it once the check-in is over.
7. **Dark and quiet colors.** Background `#0B0F1A`, a light status bar, a ring color per stage (blue, amber, red) and faint unlit ticks so the screen doesn't glare in a dark room, while every piece of text stays at 8:1 or better.
8. **Dynamic Type is on, with caps** where big text would break the layout (heading 1.3×, ring numbers 1.3×, body 1.6×, button 1.4×). The full Dynamic Type pass is backlog item BL8 / D12.
9. **No keep-awake.** Keeping the screen on during a check-in would need `expo-keep-awake` (a native package). The ladder runs in Swift with the screen locked anyway; left for later.
10. **Screen tests run on Jest's fake clock for the whole file.** Switching between fake and real timers inside the file left RNTL's cleanup unmounting the next test's tree, so the file stays on the fake clock (`Date.now` included) from start to end.

## Contract changes

None. The native module API (`src/RaveGuardNative.types.ts`, `index.ts`, `src/mock.ts`, `RaveGuardModule.swift`, `RaveGuardRuntime.swift`) is unchanged.
